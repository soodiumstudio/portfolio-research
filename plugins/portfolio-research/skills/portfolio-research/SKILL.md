# 남들은 뭘 만들었나 찾아보기

학생은 대부분 "이런 거 만들고 싶어요" 한 줄만 들고 온다. 거기서 시작해서 쓸 수 있는 조사 결과까지 데려가는 것이 이 스킬의 일이다.

---

## 0단계 — 시작하자마자 이 안내를 그대로 보여준다

학생은 이 스킬이 무엇을 해 주는지 모른 채 실행한다. 질문부터 던지지 말고 아래를 먼저 출력한다.

```
📌 이 스킬이 하는 일
   관심 있는 분야에 이미 어떤 서비스가 있는지 찾아서,
   포트폴리오에 바로 붙일 수 있는 파일 세 개로 만들어 드립니다.

📌 이럴 때 쓰세요
   · "이런 거 만들어 볼까" 생각만 있고 아직 아무것도 안 정했을 때
   · 만들고 싶은 건 있는데, 남들은 어떻게 했는지 모를 때
   · 포트폴리오에 넣을 리서치 페이지가 필요할 때

📌 이건 못 합니다
   · 사용자 인터뷰 — 사람을 직접 만나야 합니다
   · 앱을 실제로 써 본 느낌 — 직접 깔아서 써 봐야 합니다
   · 아무도 조사한 적 없는 숫자 — 없는 건 없다고 말씀드립니다

📌 준비물
   없습니다. "이런 거 만들고 싶어요" 한 줄이면 시작합니다.

📌 걸리는 시간
   질문 답하기 10분  →  조사 20~40분  →  정리 10분

그럼 시작할게요. 다섯 가지만 여쭤볼게요.
```

수업 중이라면 여기에 덧붙인다:
> 오늘 수업에서는 **질문 답하기까지만** 합니다. 조사 실행은 집에서 하세요. 여럿이 동시에 돌리면 중간에 멈춥니다.

---

## 1단계 — 조사 질문을 좁힌다 (여기가 전부다)

다섯 개를 **한 번에 하나씩** 묻는다. 다섯 개를 한꺼번에 던지면 학생이 다 대충 답한다.
질문마다 **좋은 답과 나쁜 답 예시를 함께 보여준다.** 학생은 예시를 보고 자기 답을 고친다.

**질문 1 — 어떤 분야에 관심이 있나요?**
```
❌ "앱이요"                        너무 넓어서 시작할 수 없습니다
❌ "요즘 트렌드 되는 거요"          조사가 아니라 유행 따라가기가 됩니다
⭕ "자취생이 밥 챙겨 먹는 거요"      이 정도면 충분합니다
```

**질문 2 — 누가 쓸 서비스인가요? (나이와 상황까지)**
```
❌ "20대"                          나이만으로는 아무것도 좁혀지지 않습니다
⭕ "혼자 사는 20대 직장인, 퇴근이 늦은 사람"
```

**질문 3 — 이번 조사에서 제일 알고 싶은 게 뭔가요? (딱 하나)** ← 제일 중요
```
❌ "자취생들이 뭘 원하는지"          이건 인터뷰로만 알 수 있습니다
❌ "시장 크기랑 경쟁사랑 트렌드"      세 개입니다. 하나만 고르세요
⭕ "이미 나온 앱들이 왜 자취생한테 안 먹히는지"
⭕ "밥 챙겨주는 서비스들이 돈을 어떻게 버는지"

💡 좋은 조사 질문은 '왜' 또는 '어떻게'로 시작합니다.
   '무엇'으로 시작하면 검색만 하고 끝납니다.
```
여러 개를 답하면 하나로 좁히게 한다. 나머지는 적어 두었다가 나중에 하자고 말한다.

**질문 4 — 떠오르는 비슷한 서비스가 두세 개 있나요?**
```
"모르겠어요" 도 괜찮은 답입니다. 그러면 제가 찾아서 보여드릴게요.
다만 하나라도 알고 계시면 조사가 훨씬 정확해집니다.
```

**질문 5 — 한국만 볼까요, 해외도 볼까요?**
```
포트폴리오라면 보통 한국만으로 충분합니다.
해외를 보면 "우리나라엔 아직 없는 것"을 찾기 좋습니다.
```

다섯 답을 **한 문단으로 정리해 읽어 주고 확인받는다.** 확인 전에는 조사를 시작하지 않는다.

## 2단계 — 조사한다. 단, 두 갈래로 나눠서

**이 구분을 학생에게 반드시 설명한다.** 안 그러면 학생은 AI가 다 해 준 줄 안다.

| | 검색으로 알 수 있는 것 | 직접 켜 봐야 아는 것 |
|---|---|---|
| 시장 숫자 | ⭕ 통계, 보도자료 | |
| 어떤 서비스가 있는지 | ⭕ | |
| 가격·요금제 | ⭕ | |
| 첫 화면에서 무엇을 시키는지 | | ⭕ |
| 끝내는 데 몇 번 눌러야 하는지 | | ⭕ |
| 어디서 막히고 짜증 나는지 | | ⭕ |

**AI가 하는 것** — 후보 목록, 비교 기준, 검색으로 채울 수 있는 칸까지.
**학생이 하는 것** — 직접 깔아서 나머지 칸 채우기. 숙제로 남긴다.

비교표의 모든 칸에 표시를 남긴다: `🔍 직접 확인` / `📄 검색으로만`

### 2-1. insane-research 가 있는지 먼저 확인한다

`insane-research-main` 스킬을 쓸 수 있으면 그쪽으로 넘긴다. 여러 에이전트가 교차 검증까지 해 준다.

**없으면** 학생에게 이렇게 안내한다. 조용히 검색으로 때우지 않는다.

```
깊이 있게 조사하려면 도구를 하나 더 설치해야 합니다. 두 줄이면 됩니다.

  /plugin marketplace add https://github.com/fivetaku/gptaku_plugins.git
  /plugin install insane-research

설치 후 앱을 껐다 켜세요.

지금 그냥 해 보고 싶으시면 "간단하게"라고 말씀하세요.
웹 검색만으로 10분 안에 해 드립니다. 대신 깊이는 얕습니다.
```

### 2-2. 넘길 때는 "조사 설계서"를 만들어서 넘긴다

**"자취생 밥 앱 조사해줘" 처럼 넘기지 않는다.** 1단계 답을 아래 형태로 바꿔
`research/query.json` 에 저장하고, 그 내용으로 `insane-research-main` 을 호출한다.

```json
{
  "task": {
    "title": "자취 20대의 저녁 식사 관련 서비스 현황과 빈 자리",
    "objective": "이미 나온 서비스들이 왜 자취 20대에게 자리 잡지 못했는지 밝히고, 아직 비어 있는 기회 영역 3개를 뽑는다",
    "type": "exploratory"
  },
  "context": {
    "background": "혼자 사는 20대 직장인은 퇴근이 늦어 저녁을 거르는 경우가 많다. 간편식과 배달 서비스가 늘었지만 이 집단에 특화된 서비스가 자리 잡았는지는 확인되지 않았다. 포트폴리오의 문제 정의 근거로 쓸 자료가 필요하다.",
    "audience": "general",
    "use_case": "UX/UI 포트폴리오의 리서치 페이지 작성과 문제 정의의 근거로 사용",
    "prior_knowledge": ["배달의민족", "쿠팡이츠", "마켓컬리"]
  },
  "questions": {
    "primary": "이미 나온 식사 관련 서비스들이 자취하는 20대에게 자리 잡지 못한 이유는 무엇인가",
    "secondary": [
      "이 집단을 겨냥한 서비스는 어떤 것들이 있고 각각 무엇을 내세우는가",
      "요금 구조는 어떻게 되어 있는가",
      "이용자들이 공개적으로 남긴 불만은 무엇인가"
    ],
    "exclusions": [
      "직접 인터뷰해야만 알 수 있는 개인의 동기와 감정",
      "실제 앱을 써 봐야 아는 사용 경험"
    ]
  },
  "constraints": {
    "timeframe": { "start": "2023", "end": "present", "focus_period": "최근 2년" },
    "geography": { "scope": "national", "regions": ["대한민국"] },
    "sources": {
      "required_types": ["official_docs", "industry_reports", "news"],
      "min_quality": "B",
      "language": ["ko", "en"],
      "preferred_domains": ["kostat.go.kr", "kdca.go.kr", "mfds.go.kr", "atfis.or.kr", "korea.kr"]
    }
  },
  "output": {
    "format": "comprehensive_report",
    "length": { "min_words": 1500, "max_words": 5000 },
    "structure": {
      "include_executive_summary": true,
      "include_bibliography": true,
      "include_methodology": true
    }
  }
}
```

**이 값들은 형식을 채우는 게 아니라 각각 사고를 하나씩 막는 장치다.** 반드시 채운다.

| 넣는 값 | 이게 막는 사고 |
|---|---|
| `timeframe.start` 를 최근 3년으로 | 오래된 **전망치**가 현재 수치처럼 섞여 들어오는 것 |
| `sources.language` 에 `"ko"` 추가 | **기본값이 영어라서** 국내 통계를 아예 못 찾는 것 |
| `sources.min_quality: "B"` | 개인 블로그·커뮤니티 글이 근거로 올라오는 것 |
| `sources.preferred_domains` 에 정부 통계 사이트 | 출처 등급이 뒤섞이는 것 |
| `questions.exclusions` | 인터뷰로만 알 수 있는 것을 검색으로 답하려 드는 것 |

`sources.language` 를 비우면 영어 자료만 찾는다. **국내 주제라면 반드시 `"ko"` 를 넣는다.**

원본 리포트는 `research/raw/` 에 **그대로 남긴다.** 요약만 남기면 나중에 근거를 찾을 수 없다.

### 2-3. 간단 모드 (폴백)

insane-research 가 없거나 학생이 "간단하게"라고 하면 웹 검색으로 진행한다.
출처를 최소 다섯 개 확보하고, 결과 맨 위에 적는다.

> ⚠️ 이 조사는 간단 모드로 했습니다. 포트폴리오에 넣기 전에 출처를 직접 확인하세요.

**시간이 오래 걸린다는 것을 미리 알린다.** 수업 중이라면 1단계까지만 하고 실행은 나중에 하라고 안내한다.

## 3단계 — 숫자는 이렇게 확인한다 (사고가 제일 많이 나는 곳)

실제로 검색해 보면 이런 일이 일어난다. 학생에게 이 예시를 그대로 보여준다.

```
⚠️ 실제로 있었던 일 1
   "간편식 시장 10조" 라는 숫자가 나옵니다.
   찾아보면 2019년 자료에 실린 '2025년이 되면 이럴 것이다' 전망치입니다.
   실제로 그렇게 됐는지는 아무도 확인 안 했습니다.

⚠️ 실제로 있었던 일 2
   "저녁 결식률"을 찾았는데 "아침 결식률 62.1%"가 나옵니다.
   다른 숫자입니다. 그런데 그냥 쓰면 아무도 모릅니다 — 면접 전까지는.
```

그래서 숫자마다 세 가지를 반드시 붙인다. 하나라도 없으면 그 숫자는 쓰지 않는다.

| 확인할 것 | 없거나 다르면 |
|---|---|
| 몇 년 기준 숫자인가 | 쓰지 않는다 |
| 실제로 잰 값인가, 예측인가 | `(전망치)` 라고 표시한다 |
| 내가 알고 싶던 바로 그 숫자인가 | `(대신 찾은 숫자)` 라고 표시한다 |

**출처는 등급을 매겨 표시한다.**

| 등급 | 어디 | 포트폴리오에 |
|---|---|---|
| A | 정부·공공기관 (통계청, 질병관리청, 농림축산식품부 등) | 씁니다 |
| B | 업계 리포트, 언론 보도 | 씁니다. 원자료를 찾으면 더 좋습니다 |
| C | 블로그, 커뮤니티, 요약 글 | 힌트로만. 그대로 인용하지 않습니다 |

숫자를 못 찾으면 **"찾지 못했습니다"라고 쓴다. 절대 지어내지 않는다.**
학생에게 말한다: "숫자가 없는 건 문제가 아닙니다. 없는 걸 있는 것처럼 쓰는 게 문제입니다."

## 4단계 — 파일 세 개로 정리한다

조사 리포트는 그대로 못 쓴다. 세 개로 줄인다. 모두 `research/` 아래.

**`market-summary.md`** — A4 한 장. 숫자 세 개 + 각각의 연도·등급·링크.
```markdown
| 숫자 | 연도 | 종류 | 출처 | 등급 |
|---|---|---|---|---|
| 아침 결식률 62.1% (20대) | 2024 | 실측 | 국민건강영양조사 | A |
```

**`competitor-matrix.md`** — 비슷한 서비스 네다섯 개 × 비교 기준 다섯 개.
비교 기준은 **1단계 3번 답에서 뽑는다.** 다른 데서 가져오지 않는다.
각 칸에 `🔍`/`📄` 표시와 확인한 링크.

**`opportunities.md`** — 비어 있는 자리 **정확히 세 개.** 각각:
- 무엇이 비어 있는가 (한 문장)
- 왜 그렇게 보는가 (비교표의 **어느 칸**에서 나왔는지 지목)
- 여기를 노리면 무엇이 어려울까

셋은 서로 충분히 달라야 한다. 비슷하면 고를 이유가 없다.

## 지키는 것

1. **모르면 묻는다** — 필요한 정보가 없으면 질문부터. 추측해서 진행하지 않는다.
2. **근거를 붙인다** — 숫자에는 연도와 출처, 주장에는 어디서 나왔는지.
3. **확실하지 않은 건 따로 모은다** — 맨 뒤 `## 확인 필요` 에. 본문에 섞지 않는다.
4. **길게 쓰지 않는다** — 기회는 셋, 숫자는 셋.
5. **고르는 건 학생이다** — 선택지를 좁혀 주되 결정은 학생이 한다.
6. **쉬운 말로 말한다** — 어려운 용어를 쓸 때는 괄호로 뜻을 붙인다.

결과는 학생이 지금 열어 둔 폴더에 저장한다. 다른 스킬이나 이전 결과물을 필요로 하지 않는다.

## 끝낼 때

`## 확인 필요` 에 검증 못 한 것을 모으고, 아래를 출력한다.

```
넘어가기 전에 확인하세요
□ 숫자 세 개에 전부 '몇 년 기준'이 적혀 있나요?
□ 비교표에 🔍(직접 확인) 표시가 하나라도 있나요? 전부 📄면 아직 조사가 아닙니다
□ 비어 있는 자리 세 개가 서로 다른 이야기인가요?

숙제
비교표에서 📄로만 채운 칸을 직접 앱을 켜서 확인하고 🔍로 바꾸세요.
이 작업이 리서치를 '검색'에서 '조사'로 바꿉니다.
```
